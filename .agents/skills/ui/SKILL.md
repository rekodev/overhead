# UI (Overhead)

The webview is a renderer. Rust owns the state; React shows the latest
snapshot and turns key presses and clicks into commands. Keep it that way:
UI-only state is limited to things like the selected row, an open text
field's draft, or which card is flipped to the other density.

Visual language: **calm**. Small, quiet, no mascot, no idle animation.
Motion only where it carries meaning (the working pulse, the fade-in/out).

## Layout

```
src/
  main.tsx, App.tsx
  bindings.ts            generated by tauri-specta; never edit
  store/snapshot.ts      the snapshot store (useSyncExternalStore)
  components/<area>/     pill/, panel/, cards/, settings/, onboarding/
  hooks/                 reusable stateful logic (useKeymap, useSelection)
  lib/                   pure helpers (formatters, diff stats, key matching)
  constants/             keymap table, timings, copy that isn't per-component
  types/                 UI-only types (Rust types come from bindings.ts)
```

One component per file, named after it in kebab-case
(`permission-card.tsx` → `PermissionCard`). Pure logic goes in `lib/`, not
inside components.

## Snapshot store

- `store/snapshot.ts` subscribes once to the snapshot event from
  `bindings.ts` and keeps the latest value. Components read it with
  `useSyncExternalStore` through a small hook (`useSnapshot(selector)`).
- No Zustand, Redux or React context for app state. Don't copy snapshot
  data into `useState`.
- Mutations go through the generated command functions. Don't update the
  UI optimistically: the next snapshot is the answer. Show a pending state
  on the button until it arrives.
- Handle the empty snapshot (no sessions: the pill hides) and a failed
  command (inline message on the card).

## Keyboard

- Card keys work only while the panel has focus. Match on
  `KeyboardEvent.key` (the character), never `code`, so every layout works.
  Digits 1–8 also accept the Lithuanian number-row characters
  (ą č ę ė į š ų ū).
- The keymap is one table in `constants/keymap.ts`, read by both the
  dispatcher and the button hints. A button's key hint and its handler must
  never disagree.
- In text fields, letters type normally; only Enter and Esc act.
- Esc: leave the text field first, then release focus (a Rust command).
- Every button shows its key hint and also works with the mouse.

## Density

Minimal and Detailed come from settings (default Detailed). `I` flips one
card. Model + effort show only in Detailed. Write a card's Minimal view first
and add detail to it; don't build two separate cards.

## Styling

- Tailwind v4 utilities. Shared colours and sizes go in `@theme` in
  `src/index.css`; add a token rather than repeating a raw value.
- State colours: working white (pulsing), needs-you orange, done-unseen
  blue. Use the tokens, never a one-off hex.
- Text from Claude, prompts, paths and commands is untrusted: render as
  text, never `dangerouslySetInnerHTML`. Plans are Markdown: render them with
  a sanitising renderer and no raw HTML.
- Respect `prefers-reduced-motion` for the pulse and fades.
